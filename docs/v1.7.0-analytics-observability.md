# v1.7.0 — Analytics & Observability expansion

Status: IMPLEMENTATION IN PROGRESS. Not approved for release. Ground Up and new client tracking are out of scope.

## Delivered in initial branch
- Admin dashboard: existing 24-hour/7-day/30-day active profiles, registrations and play trends.
- New read-only count metrics: weekly daily reward claims, achievement awards, privileged audit records and unresolved reports.
- All-time top published games from existing counters, plus grouped privileged audit action categories.
- Honest sampling warnings; no false claim that a capped PostgREST response represents the entire dataset.
- No extra event collection, hidden user tracking, or new exposure of personal information.

## Required for a full observability release
1. **Server-side operations:** structured allowlisted event codes for cron start/success/failure, Discord gateway connectivity, health checks, authentication security failures, reward RPC failures, and database job outcomes. Never log secrets, passwords, session tokens, raw IPs, private messages, search text, URLs containing query parameters or arbitrary request payloads. Use bounded details, severity, generated correlation ID and redacted error category.
2. **Security:** retain privileged moderation and admin audit trails; make audit logging tamper-resistant, deny client inserts/updates, enforce least privilege, and test cross-account isolation.
3. **Telemetry:** explicit opt-in for optional UX measurements. Separate diagnostic and usage consent if needed; honor Global Privacy Control, refusal, withdrawal and deletion. No session replay or fingerprinting.
4. **Scale:** prefer materialized/coarse daily database aggregates to fetching 10,000 rows. Include query time, missing data, time windows, unique definitions and sample-size warnings.
5. **Dashboard:** authorized operational health and trends, failure/error rates, game launch failures, successful completions, mobile input classes, accessibility issues, uptime, queue delays, latency histograms and build/release comparisons. Any small-group device/cohort breakout must obey >=20-subject disclosure floor.
6. **Data lifecycle:** approved event inventory and legal basis, bounded retention, deletion jobs, audit of processor access and deletion tests. Younger users must have high-privacy defaults; never infer age from behavior.
7. **Acceptance:** disposable fresh migrations, SQL RLS/RPC checks, two-account privacy tests, no-consent network audit, browser accessibility, CI, worker/cron staging smoke, backups and rollback rehearsal.

## Operational semantics
- `active today` currently counts profiles with a recent last-seen timestamp; it is not unique anonymous visitors.
- `plays` counts recorded authenticated game sessions. It does not include anonymous play or pageviews.
- `top games` uses all-time counters; `audit action categories` is capped at 1,000 entries.
- Zero and missing access rights are not equivalent. Current dashboard needs explicit query-error presentation.
- Never use raw activity events to rank individuals or encourage compulsive engagement.

## Release gate
Do not merge or activate new collection until security, consent, retention, and child-privacy approvals are complete. The initial dashboard changes use existing data only.
